# 插件设置与常见问题

在 magpie 中打开「Claude 中文」。页面分为「语言设置」和「资源维护」两个标签，浏览器工作台也使用同一套页面。

### 选择汉化方式

「语言设置」默认使用「启动时加载」。选择简体或繁体，启用「启动时自动中文」，保持喜鹊运行，再从原入口启动 Claude。页面会显示准备、等待退出、就绪、正在加载以及最近一次加载结果。停用仅影响后续启动。

切换方式需要确认。确认后会保存新选项并停用自动加载。回到「启动时加载」后，需要手动开启「启动时自动中文」。

选择「写入安装资源」后，页面会显示当前安装是否兼容。支持此方式的是兼容且可写的 Windows 非 MSIX 解包版。请通过「文件 → 退出」关闭 Claude，再点击「写入所选语言」，核对目标目录和语言后确认。插件会先备份原文件。再次更改语言后，需要重新点击写入。资源在退出喜鹊后仍然生效，应用更新可能替换它们。

微软商店版受系统保护，请使用「启动时加载」。官网 MSIX 可以尝试「内置补丁」，但通常需要接管安装目录的写入权限；前端封装在 ASAR 的版本还可能启用完整性校验。

已写入的资源需要手动恢复。可在「语言设置」点击「恢复原始资源」，恢复完成后才能重新启用自动加载。若上次写入在准备备份时中断，第一次恢复可能回到上次已应用状态，请按提示再次恢复。遇到版本或备份哈希不匹配，可在「资源维护」查看结果。

选择「内置补丁（需管理员）」后，先完全退出 Claude，再点击「应用中文补丁」。插件会显示目标路径，执行前再次检查 `claude.exe` 和 `cowork-svc.exe` 是否仍在运行，然后启动固定安装器并请求 UAC。安装器会写入中文资源、同步程序完整性哈希，并从原入口打开 Claude。恢复时点击「恢复原样」，从补丁的 `.zh-cn-backups` 备份还原。

内置补丁会修改程序文件，可能使 Claude 签名失效。官网 MSIX 安装可能需要接管安装目录的写入权限；恢复补丁不会自动还原目录所有者或 ACL。微软商店版受系统保护，不使用此方式。安装器来源、提交和恢复限制见[内置补丁说明](third-party-patch.md)。

语言、方式和自动加载偏好保存在插件状态目录中。插件为新原位事务使用其中的 `resource-backup` 子目录，已有旧事务继续使用原备份。浏览器工作台与插件页共用设置，其他宿主更改偏好后，旧页需要重新打开。浏览器入口由 `claude_zh_workbench` 工具提供，会话地址仅供自己使用。

## 侧栏提示「127.0.0.1 拒绝连接」

打开插件页时，喜鹊通过本机回环地址连接工作台。多个喜鹊宿主共用同一份插件时，侧栏沿用仍有效的会话。宿主退出后，页面会重新连接并读取已保存的设置。若保存期间断开，请在重连后核对设置。

仍无法连接时，可在当前喜鹊实例调用 `claude_zh_workbench`，直接在本机打开它返回的私有地址。`claude_zh_sync_status` 中的 `sidebar: publication-failed` 表示插件未能发布侧栏地址，可检查插件安装目录的写入权限。反馈问题时只需附端口和状态，请省略地址里的 `#token`。

## 查看版本

「Claude 中文」页面在 logo 下方显示当前安装版本。点击「claude-desktop-zh」打开项目仓库，点击「看看他还做了什么」打开作者主页。公开版本见 [npm](https://www.npmjs.com/package/magpie-claude-zh)，更新说明见 [GitHub Releases](https://github.com/polang233/claude-desktop-zh/releases)。反馈时请附上插件版本、Claude 版本和加载状态。

## 没有出现准备完成通知

先确认 Claude 已通过「文件 → 退出」完全退出；关闭窗口可能只是缩到托盘。Windows 通知也可能被系统通知设置隐藏。

可在 magpie 中通过 `claude_zh_sync_status` 查看状态：`waiting-for-normal-exit` 表示仍在等待退出，`watching` 表示已准备好，`Applied` 表示本次中文已加载。

## 启动时弹出窗口

加载中文时会短暂打开调试窗口和文件选择框。请保持 Claude 在前台，等待它们自动收起；如果停住，保留现场并记录插件状态。

## Claude 更新后没有加载中文

插件会检测安装版本变化并自动重建语言包。在「资源维护」刷新状态，看到已就绪后，从原入口打开 Claude。如果上一轮启动发生在重建期间，请正常退出再打开。重建失败时，页面会显示原因。

## macOS 支持

目前只支持只读检查和计划，不修改应用资源或签名，因此不能完成自动汉化。
